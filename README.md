# プロンプトライブラリ

庁内向けに、生成AIで使えるプロンプトを共有するための静的サイトです。
このファイルは、サイトを**管理・更新する職員向け**の説明です。

---

## 概要

- プロンプトの原本は `prompts/` 配下の Markdown ファイルです。
- 追加・修正は Markdown を1ファイル置くだけで完了します（1ファイル＝1プロンプト）。
- 検索・絞り込み・コピーはすべてブラウザ内で動作します。
- データベース、サーバサイド処理、外部API、CDN、ビルド工程はいずれも使用していません。

### ファイル構成

```text
/
├─ index.html          画面（1ページのみ）
├─ web.config          IIS 用の MIME 設定
├─ prompts/            プロンプト本体（Markdown）
│  └─ meeting-minutes.md など
├─ data/
│  ├─ manifest.json    読み込む Markdown の一覧
│  └─ tags.json        カテゴリとタグの定義
├─ css/style.css
└─ js/
   ├─ app.js           一覧・検索・詳細表示
   └─ markdown.js      「使い方」欄の簡易 Markdown 描画
```

## 動作方法

### 動作環境

Microsoft Edge、Google Chrome、Firefox の現行版で動作します。
Internet Explorer には対応していません。

**Web サーバ経由で開く必要があります。**
`index.html` をダブルクリックして開くと、ブラウザの制限により Markdown を読み込めません。

動作確認だけなら、フォルダ内で簡易サーバを起動するのが手軽です。

```powershell
# Python が入っている場合
python -m http.server 8000
# → ブラウザで http://localhost:8000/ を開く
```

---

## IIS への配置方法

1. このフォルダ一式を、IIS の公開ディレクトリへコピーします。
   （例：`C:\inetpub\wwwroot\prompt-library\`）
2. IIS マネージャーで、そのフォルダを**アプリケーション**または**仮想ディレクトリ**として設定します。
3. ブラウザで `http://<サーバ名>/prompt-library/` を開きます。

### 注意点

- **`web.config` を必ず一緒に配置してください。** IIS は既定で `.md` を配信せず、
  無いとプロンプトが 404 になります。`web.config` が使えない環境では、
  IIS マネージャーの「MIME の種類」で `.md` → `text/markdown` を手動追加してください。
- サブディレクトリ配置に対応しています。パスはすべて相対で解決するため、
  `/` 直下でも `/tools/prompt-library/` でも設定変更なしで動作します。
- 更新が反映されない場合はブラウザのキャッシュを削除してください
  （Markdown は `no-cache` で取得しますが、`css`・`js` はキャッシュされます）。

## プロンプトの追加方法

### 1. Markdown ファイルを作る

`prompts/` に新しいファイルを作成します。
ファイル名は**半角英小文字・数字・ハイフン**にしてください（例：`budget-summary.md`）。
ファイル名から拡張子を除いたものが、そのままURLの識別子になります。

### 2. `data/manifest.json` に登録する

静的サイトではフォルダ内のファイルを自動で一覧できないため、
追加したファイル名をここに書き足します。**この登録を忘れると画面に出ません。**

```json
{
  "prompts": [
    "meeting-minutes.md",
    "budget-summary.md"
  ]
}
```

- 記載した順にカードが並びます。
- 末尾の要素にカンマを付けないでください（JSON の構文エラーになります）。
- 削除するときは、Markdown ファイルとこの行の両方を消します。

### 3. ブラウザで表示を確認する

一覧に出ること、詳細が開くこと、「プロンプトをコピー」で意図した文面がコピーされることを確認します。

## front matter の記述方法

Markdown の先頭に `---` で挟んだ領域を置き、次の4項目を記載します。

```yaml
---
title: 会議メモから議事録を作成
category: 文書作成
tags:
  - 会議
  - 議事録
  - 要約
description: 箇条書きの会議メモを、共有可能な議事録形式に整理します。
---
```

| 項目 | 必須 | 内容 |
| --- | --- | --- |
| `title` | ○ | 一覧・詳細に出る名前。30字程度まで |
| `category` | ○ | 大分類。1つだけ。下記の定義済みカテゴリから選ぶ |
| `tags` | － | 0〜5個程度。1行1個、行頭は半角スペース2つ＋`- ` |
| `description` | ○ | 一覧カードに出る1行説明。40字程度まで |

記述上の注意：

- `---` は**行頭**に置き、前に空行やスペースを入れないでください。
- `:` の後には**半角スペース**を1つ入れてください。
- 値に `:` や `#` を含めたい場合は `title: "対応方針：検討用"` のように引用符で囲みます。
- タグを書かない場合は `tags:` の行ごと省略してください。

### 本文の構成

```markdown
# 会議メモから議事録を作成

## 使い方

会議中に取ったメモを、プロンプト末尾に貼り付けて使用します。

## プロンプト

あなたは行政文書の作成補助者です。

以下の会議メモを……
```

- **`## プロンプト` 以下が「コピー」の対象**です。ここには生成AIへ実際に入力する文面だけを書きます。
- `## 使い方` は補足説明です。段落と箇条書き（`- `、`1. `）が使えます。
- `## プロンプト` が無い場合は本文全体がコピー対象になり、詳細画面に注意書きが出ます。
- 貼り付け位置は `（ここに会議メモを貼り付けてください）` のように明示すると親切です。
- **実在の個人情報・機密情報は書かないでください。**

## カテゴリ・タグの追加・変更方法

定義は `data/tags.json` にまとめています。

```json
{
  "categories": ["文書作成", "文章改善", "企画・検討", "調査・整理", "業務改善", "データ・IT"],
  "tags": ["要約", "校正", "会議", "議事録", "アイデア出し", "比較", "分析", "住民向け", "庁内向け", "事業者向け"]
}
```

- **カテゴリ**は「どの業務領域に置くか」を表す大分類です。1プロンプトにつき1つ。
  部署名では分類しません。増やしすぎると選びにくくなるため、追加は慎重に判断してください。
- **タグ**は「用途・場面・対象」を横断的に表すものです。表記揺れを防ぐため、
  原則としてこの一覧にあるものから選んでください。
- 記載した順に画面へ並びます。
- 一覧に無いタグを Markdown 側で使っても表示は壊れませんが、絞り込みの末尾に追加表示されます。
  継続して使うタグは、この `tags.json` にも追加してください。
- 使われていないタグは絞り込みに表示されません（定義だけ残しておいても問題ありません）。

### カテゴリ名を変更するとき

`data/tags.json` と、該当する Markdown すべての `category:` の両方を書き換えてください。
片方だけ直すと、未定義のカテゴリとして絞り込みの末尾に表示されます。

## 画面でできること

- キーワード検索（タイトル・説明・カテゴリ・タグ・プロンプト本文が対象。空白区切りでAND検索）
- カテゴリによる絞り込み（1つ選択）
- タグによる絞り込み（複数選択。選ぶほど件数が絞られます）
- 絞り込み条件の表示と個別解除・一括解除
- プロンプト本文のワンクリックコピー（一覧カードからも可能）
- キーボード操作：`/` で検索欄へ、`Esc` で一覧に戻る／絞り込み解除

詳細画面の URL は `index.html#meeting-minutes` の形式です。
特定のプロンプトを案内するときは、この URL をそのまま共有できます。
